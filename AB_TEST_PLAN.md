# A/B Test

## Описание проекта

Сервис предсказания вероятности дефолта по кредитным картам на основе исторических данных клиентов UCI Credit Card Dataset.

### Цель A/B теста

Проверить гипотезу, что модель v2 с улучшенной архитектурой (больше деревьев, меньший learning rate, контроль переобучения) превосходит baseline модель v1 по метрике F1-score на production-данных.

---

## Архитектура моделей

### Model v1 (Baseline)

```python
GradientBoostingClassifier(
    n_estimators=100,
    learning_rate=0.1,
    max_depth=5,
    random_state=42
)
```

**Характеристики:**
- Стандартная конфигурация GBM
- Быстрое обучение (~10-15 сек)
- Сбалансированный bias-variance tradeoff

### Model v2 (Experimental)

```python
GradientBoostingClassifier(
    n_estimators=150,      # +50% деревьев
    learning_rate=0.05,    # -50% шаг обучения
    max_depth=6,           # +1 глубина
    min_samples_split=10,  # защита от переобучения
    random_state=42
)
```

**Изменения:**
- Более глубокие деревья для захвата сложных паттернов
- Медленный learning rate для стабильности
- Регуляризация через min_samples_split

# A/B Test: Credit Default Model v1 vs v2

## 🎯 Обзор эксперимента

**Цель:** Проверить, улучшает ли модель v2 качество предсказаний дефолтов в production-среде.

**Контекст:** Модель v2 показала F1-score на 0.88% хуже на тестовой выборке (v1: 0.4679, v2: 0.4638). Требуется валидация на реальных production-данных для окончательного решения о внедрении.

---

## 🔬 Гипотезы

### Основная гипотеза (H1)

H0: F1_v2 ≤ F1_v1
H1: F1_v2 > F1_v1 + 0.02 (статистически значимое улучшение >2%)


### Дополнительные гипотезы

- **H2:** Precision_v2 > Precision_v1 (снижение False Positives — меньше отказов платёжеспособным клиентам)
- **H3:** Recall_v2 > Recall_v1 (увеличение True Positives — больше выявленных дефолтов)
- **H4:** Expected_Loss_v2 < Expected_Loss_v1 (снижение ожидаемых финансовых потерь)

---

## 📊 Метрики

### Технические метрики

| Метрика | Target | Описание |
|---------|--------|----------|
| **F1-score** (primary) | +2% от baseline | Гармоническое среднее Precision и Recall |
| **Precision** | >0.65 | Доля корректных предсказаний дефолта |
| **Recall** | >0.37 | Доля найденных реальных дефолтов |

### Бизнес-метрики

| Метрика | Target | Описание |
|---------|--------|----------|
| **Expected Loss Reduction** | >5% | Снижение ожидаемых потерь по портфелю |
| **Approval Rate** | Падение <5% | Доля одобренных заявок (guardrail метрика) |

### Операционные метрики

| Метрика | Target | Описание |
|---------|--------|----------|
| **Latency (p95)** | <100ms | 95-й перцентиль времени ответа |
| **Error Rate** | <0.1% | Доля запросов с ошибками |

---

## 🧪 Дизайн эксперимента

| Параметр | Значение |
|----------|----------|
| **Тип теста** | Randomized A/B test |
| **Распределение трафика** | 50% v1 / 50% v2 |
| **Длительность** | 14 дней |
| **Размер выборки** | 10,000 запросов на группу (20,000 total) |
| **Уровень значимости** | α = 0.05 |
| **Мощность теста** | 1 - β = 0.80 |
| **Randomization Unit** | Индивидуальный запрос |
| **Метод рандомизации** | Python random.random() |

---

## ✅ Критерии успеха

### Внедрить v2, если выполнены ВСЕ условия:

1. F1_v2 > F1_v1 + 0.02
2. p-value < 0.05 (статистическая значимость)
3. Expected Loss reduction > 5%
4. Latency p95 < 100ms
5. Error rate < 0.1%

### Отклонить v2, если выполнено ЛЮБОЕ условие:

1. F1_v2 < F1_v1 (регрессия качества)
2. p-value > 0.05 (нет статистической значимости)
3. Latency p95 > 150ms (деградация производительности)
4. Error rate > 0.5% (проблемы стабильности)
